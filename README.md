# Лендинг KV-web

Статичный сайт по макету Figma «Лендинг (Copy)» → `Frame 27945` (1440 × 16474).
Ни сборки, ни зависимостей: три файла + папка картинок.

```
index.html        вся разметка (RU-тексты + ключи data-i18n)
privacy.html      политика конфиденциальности RU  (privacy-en.html — EN)
style.css         стили + адаптив
script.js         квиз, формы, табы, глобус, виджеты
i18n.js, i18n/    переключение RU/EN и английский словарь
fonts/            шрифты self-hosted (Archivo, Montserrat)
vendor/           three.js r128 для 3D-глобуса
img/              картинки в webp
sitemap.xml, robots.txt
```

## Две языковые версии (RU / EN)

Один `index.html` на оба языка, без сборки. Русский текст в разметке — источник правды,
английский лежит словарём в `i18n/en.js`, подстановку делает `i18n.js`.

```
i18n.js        движок: T()/TD(), подстановка в DOM, переключатель RU/EN
i18n/en.js     словарь EN: { 'ключ': 'текст', plans: {...}, hubs: {...} }
i18n/check.py  проверка: python i18n/check.py — какие ключи без перевода
```

**Как определяется язык.** Инлайн-сниппет в `<head>` (до загрузки CSS, поэтому без мигания):
`?lang=en|ru` в URL → сохранённый выбор (`localStorage.kv_lang`) → язык браузера
(`ru/be/uk/kk/ky/uz/tg` → RU) → часовой пояс (Минск/Москва/Алматы и т.п. → RU) → иначе EN.
Переключатель RU/EN в шапке запоминает выбор и перезагружает страницу.

**Как править тексты, чтобы не разъехались версии:**

1. Новый текст в `index.html` пишем по-русски и вешаем ключ: `<p data-i18n="раздел.что-это">Текст</p>`.
   Для атрибутов — `data-i18n-alt`, `data-i18n-placeholder`, `data-i18n-title`, `data-i18n-aria-label`.
   Если внутри есть `<b>`, `<br>`, `<span class="accent">` — в словаре EN пишем строку с той же разметкой.
2. Добавляем перевод в `i18n/en.js`: `'раздел.что-это': 'Text',`. Нет ключа → на EN останется русский, ничего не сломается.
3. Строки в `script.js` оборачиваем: `T('ключ', 'русский текст')`, с подстановкой — `T('ключ', 'Шаг {n}', { n })`.
   Данные-структуры (тарифы `PLAN_DATA`, города `HUBS`, лиды) уже обёрнуты в `TD('plans', {...})` —
   в `en.js` под тем же ключом лежит зеркальная структура, переводятся только строки.
4. `python i18n/check.py` — покажет ключи без перевода, лишние ключи и русский текст без `data-i18n`.

**Особенности EN-версии:** цены — те же цифры, но в `$` (`от 1 390 BYN` → `from $1,390`);
слово «Беларусь» сведено к минимуму. Зарубежным заказчикам нигде не обещаем договор, инвойсы и
валютные контракты (юрлица для работы с ЕС нет) — только «условия фиксируем письменно», оплата
PayPal / карта / crypto. Регионы глобуса при необходимости скрываются для EN через
`i18n/en.js` → `__config.hideHubRegions` (сейчас пусто), элементы разметки — через `data-lang-only="ru"`
(так скрыта карточка «Продвижение на Яндекс» в EN). Ссылки, которые в EN ведут на другую страницу, —
через `data-i18n-href` (политика конфиденциальности → `privacy-en.html`).

## Как открыть

Двойной клик по `index.html` — работает как есть, из файла.
Локальный сервер (если нужен «как на хостинге»):

```bash
python -m http.server 8123
```

## Как выложить

Залить содержимое репозитория в корень хостинга. Никакого `npm install` и сборки не требуется.

**Чек-лист перед публикацией (плейсхолдеры, которые надо заменить):**

| Что | Где | Сейчас |
|---|---|---|
| Домен | `index.html` (canonical, og:url, og:image, JSON-LD), `sitemap.xml`, `robots.txt`, `privacy*.html` | `https://moggerrescure.github.io/information` — если переедете на свой домен, заменить поиском по файлам |
| Контакты | `script.js` → `CONTACT`, подвал и панель в `index.html`, JSON-LD | реальные: +375 (29) 252-80-43, krutko.marketing@gmail.com, @sq_dbl |
| Куда падают заявки | `script.js` → `FORM_CONFIG.ENDPOINT` | Cloudflare Worker `kv-web-leads` (см. раздел ниже) |
| Реквизиты оператора | `privacy.html`, `privacy-en.html` | блоки `[в скобках]` |
| Логотипы клиентов | `index.html`, `.clients__grid` | пустые `alt` — вписать названия |

После замены поднять версию `?v=` у `style.css`, `script.js`, `i18n.js`, `i18n/en.js` в `index.html`.

## Куда падают заявки

Контакты на странице: `+375 (29) 252-80-43`, `krutko.marketing@gmail.com`,
[Telegram @sq_dbl](https://t.me/sq_dbl), [WhatsApp](https://wa.me/375292528043).

Все 4 формы (квиз, аудит, «на своих условиях», нижняя заявка) проверяют телефон
и отправляют письмо. Пока `ENDPOINT` в `script.js` пустой, письмо идёт через
[FormSubmit](https://formsubmit.co) на `krutko.marketing@gmail.com`.
Первая заявка не дойдёт, пока в этом ящике не нажать ссылку подтверждения
от FormSubmit.

Чтобы заявка сама падала и на почту, и в Telegram, задеплойте `worker/`:

```bash
cd worker
npx wrangler login
npx wrangler secret put TELEGRAM_BOT_TOKEN
npx wrangler secret put TELEGRAM_CHAT_ID
npx wrangler secret put WEB3FORMS_ACCESS_KEY
npx wrangler deploy
```

URL воркера впишите в `FORM_CONFIG.ENDPOINT` в `script.js`. Секреты в репозиторий
не кладутся. Токен бота на странице не светится.

WhatsApp с сайта сам заявку не получает: это кнопка «написать». Push в WhatsApp
нужен платный Business API, его здесь нет.

Проверка логики воркера и ссылок: `node --test worker/lead.test.mjs test/contact-links.test.mjs`.

## Шрифты

Шрифты лежат локально в `fonts/` (`fonts/fonts.css`). Если купите оригиналы: положите `.woff2` туда же

первыми — подхватится автоматически, больше править нечего.

## Моушн и мобильные решения

Логика в `script.js`, стили — в блоке «МОУШН» в `style.css`.

**Принцип:** контент виден по умолчанию. Блоки «взводятся» (`.is-armed`) только
из JS, поэтому при отключённом или упавшем скрипте страница показывает всё как
есть. Плюс подстраховка: если блок уже на экране, а наблюдатель молчит, он
открывается принудительно.

Что есть:

- **Первый экран** — строки заголовка выезжают из-под маски, следом текст, кнопка
  и картинка. Один поставленный вход вместо одинакового «всплытия» на каждой секции.
- **Списки** идут стаггером (плитки, тарифы, кейсы, статьи), одиночные карточки —
  коротким подъёмом на 380 мс. Задержки расставляет JS через `--i`.
- **Цены** досчитываются до значения при попадании в кадр.
- **Индикатор прочитанного** сверху — ориентир на странице в 17 экранов.
- **Шапка** — постоянной высоты. Сжатие и уезжание при скролле убраны:
  sticky-элемент занимает место в потоке, поэтому смена его высоты дёргала
  весь контент под ним на каждом движении колеса.
  Прячется, когда квиз или форма и так на экране — дублировать призыв незачем.
- **Фильтры и табы тарифов** на телефоне — горизонтальная лента со снапом.
  Экономит ~200 px высоты против трёх рядов и попадать пальцем проще.
- **Параллакс** — только мышь и экран >760 px. На тач-скролле он даёт рывки,
  поэтому там не включается вовсе.

`prefers-reduced-motion: reduce` гасит всё: параллакс, счётчики, хореографию,
блик на кнопках и индикатор прогресса. Контент при этом виден сразу.

Контраст полупрозрачного белого текста на тёмных подложках поднят до ≥4.5:1 —
в макете часть подписей была на грани нечитаемости.

## Сверка с макетом

Ширины контента взяты из макета, их три (не одна):

| Ширина | Что на ней |
|---|---|
| **1160** | базовая сетка секций: квиз, кейсы, тарифы, продвижение, этапы, футер, нижняя форма |
| **1270** | шапка, первый экран, карточка отзывов, клиенты |
| **1360** | широкие карточки: «Почему мы», аудит, «на своих условиях», блог |

Проверено на 1440 px: все 18 ключевых блоков совпадают с макетом по ширине.

**Карта.** 27 булавок расставлены по координатам из макета (пересчёт из системы
Component 32 в систему картинки: карта занимает нижние 82.36 % фрейма).
Две булавки из выгрузки (Component 30/31) падали в южную Атлантику, где в
отрисовке макета их нет — не выводим.

**Клиенты.** Сетка 6×3 = 18 плиток, пропорция плитки 182×71 как в макете.

Все 18 логотипов настоящие. В выгрузке Make они лежали векторными слоями внутри
дерева React-компонентов и по отдельности не доставались, поэтому узел
`Group 27737` (id `309:5848`) выгружен из Figma отрисовкой в 2× и нарезан на
18 плиток: `img/client-r{ряд}c{колонка}.webp`. Логотипы попали на страницу
ровно такими, как в макете, вместе с подложками — включая повторы MEDEL,
MOSKVA и will chair во втором и третьем ряду: так в макете.

У плиток `alt=""`, стена логотипов подписана на уровне списка
(`aria-label="Логотипы клиентов агентства"`). Нужны имена брендов в alt —
проставьте вручную.

Поменяется состав клиентов — проще перевыгрузить узел из Figma и нарезать
заново тем же способом, чем собирать плитки по одной.
